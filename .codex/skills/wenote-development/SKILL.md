# WeNote 开发流程

这个 skill 适用于 WeNote 仓库中的功能开发、Bug 修复、重构、测试、文档和工程维护。它把用户需求落实为本地账本记录，在独立 worktree 中用 TDD 完成实现，自我验收后交给用户验收，并在用户明确确认后合并和清理。

先阅读 [仓库开发工作流](../../../docs/开发工作流.md) 和 [开发账本](../../../docs/开发账本.md)。需要创建或更新任务记录时，使用 [任务记录模板](references/任务记录模板.md)。

## 需求分类

根据主要目标选择一个类型。

- `feature` 用于新功能、接口或用户能力。
- `bugfix` 用于已确认的错误、回归或数据问题。必须有回归测试，或者在任务记录中说明无法自动化的原因。
- `refactor` 用于保持行为不变的结构、性能或可维护性调整。
- `test` 用于测试夹具、测试入口和验收基础设施。
- `docs` 用于产品、接口、开发和运维文档。
- `chore` 用于构建、依赖、脚本、配置和其他工程维护。

任务 ID 使用 `<TYPE>-YYYYMMDD-<short-name>`。类型可以用大写或小写，账本中的类型保持统一。影响面至少标记 `server`、`web`、`desktop`、`android` 之一。

## 开始任务

仅在用户要求具体实现时创建任务 worktree。设计讨论、代码评审和状态查询可以直接处理。

1. 检查当前分支、工作区和已有 worktree，确认主工作区的无关改动不会被带入任务。
2. 从基线分支创建独立 worktree 和 `codex/<type>-<short-name>-<yyyymmdd>` 分支。优先把 worktree 放在仓库同级目录，例如 `../we-note-FIX-20261123-sync-cursor`。
3. 在任务 worktree 中更新 `docs/开发账本.md`，新增任务摘要、类型、影响面、状态和分支。
4. 创建 `docs/tasks/<任务 ID>.md`，记录原始需求、范围、验收条件、测试命令、运行环境和交付计划。
5. 账本状态设为 `IN_PROGRESS`，并在任务记录中写入基线提交和 worktree 路径。

不要在主工作区直接实现任务代码，也不要把用户已有未提交改动复制到任务 worktree。

## TDD 循环

采用红、绿、重构的循环。红阶段让测试准确暴露需求或 Bug，绿阶段用最小实现通过测试，重构阶段在全绿基础上整理结构并保持行为契约。

1. 阅读相关实现、既有测试、设计文档和调用方。
2. 把验收条件转成最小失败测试。Bug 修复先写能复现问题的测试。
3. 运行聚焦测试，确认失败原因对应当前需求，并把命令和结果写入任务记录。
4. 编写最小实现，让失败测试通过。
5. 运行聚焦测试和受影响模块的回归测试。需要时补充协议、跨端、构建或端到端验证。
6. 测试全绿后再重构。运行 `git diff --check`，并检查变更范围、任务记录和账本。

每次改动都记录真实命令和退出状态。文档或配置任务可以用链接检查、格式检查、构建和启动验证代替代码测试。人工验收项要写出步骤和预期观察结果。

## 独立服务端与客户端交付

服务端变更从任务 worktree 启动独立实例，使用独立端口和该 worktree 的运行目录。

```sh
cd ../we-note-<task-id>
./scripts/local.py start --port <unique-port>
./scripts/local.py status
curl -fsS http://127.0.0.1:<unique-port>/healthz
```

交付记录必须包含服务地址、PID、日志路径、测试账户或初始化步骤和停止命令。服务端验收完成后停止该实例。

Web 客户端从任务 worktree 构建。

```sh
npm ci --prefix apps/web
npm run build --prefix apps/web
```

桌面和 Android 客户端按任务目标构建，并记录产物路径、安装或启动命令、服务端地址以及已验证的功能路径。客户端验收期间不要从主工作区构建。

## 交付与合并

自我验收完成后，逐项核对验收条件、测试结果、`git diff --check`、服务端隔离和客户端入口。把账本改为 `DELIVERED`，保留任务分支和 worktree，向用户交付任务 ID、分支、worktree、任务记录、验收命令、服务地址或客户端产物、未验证项和停止服务命令。

不要在用户确认前合并、删除 worktree 或删除分支。用户明确确认后，在基线分支合并任务分支，重新运行必要验收，停止独立服务，更新账本为 `MERGED`，写入合并提交和清理时间，再删除 worktree 与任务分支。发现基线前进、冲突、未预期未提交文件或服务未停止时保护现场并记录原因。

用户验收要求修改时沿用原分支和 worktree，将账本改为 `CHANGES_REQUESTED`，回到 TDD 循环后再次交付。需求超出原范围时更新任务记录，必要时拆分新任务。
