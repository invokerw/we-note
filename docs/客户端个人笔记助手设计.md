# 客户端个人笔记助手设计

讨论稿 · 2026-11-27 · 待产品验收

用户在 WeNote 里打开「笔记助手」，粘贴几句会后速记，说「整理成纪要，存到项目目录」。助手给出文件名和 Markdown 正文。用户还可以说「把预算那段删掉」，看过最终稿后点「创建笔记」，再点结果中的路径打开它。已有笔记也走这个入口，例如「把这篇周报的联调日期从周三改到周五」。此时只需对照改动的那一句。

已确定采用 **Pi Agent Core**，让对话、工具调用和改动预览运行在当前客户端。首版用现有的 `wenote-notes` Skill 指导写作，用已经交付的 WeNote MCP 工具读写当前库。**已确定的边界**是纯客户端助手。用户在这台设备上填写模型服务地址、模型 ID 和可选密钥。客户端直接请求该地址。对话历史存于本机，生成所需的上下文和该服务的鉴权凭据只发往用户配置的模型端点。笔记保存后的同步沿用已有机制。首版开放的模型协议和写入交互仍待讨论。

## 1. 用户从哪里开始

| 场景 | 用户操作 | 助手给出的结果 |
| --- | --- | --- |
| 从零写一篇 | 在空库或列表中点工作区右上角的助手开关，粘贴素材，说「写成会议纪要」 | 展示建议目录、文件名和可展开的完整草稿。缺少负责人或日期时保留「待定」。用户可改名、调整目录或继续修改草稿 |
| 修改手头的笔记 | 打开笔记后点同一个助手开关，说「把联调改到周五」 | 输入区带可移除的当前笔记引用。若命中唯一原句，展示原句和改后文字。若有两处可能命中，列出带上下文的候选段落 |
| 从几篇资料归纳 | 点「引用笔记」，选择两篇访谈记录，说「提炼共同意见，另存一篇」 | 回答附可点开的来源笔记。新笔记预览与来源分开，原访谈仍可单独打开核对 |
| 补一张导图 | 打开导图，说「在产品调研下面加两个子主题，用户访谈和竞品分析」 | 展示父节点的完整层级和拟新增的两个子节点。若图中有两个「调研」，先让用户选分支 |
| 只想问问 | 说「上次讨论联调得出了什么结论？」 | 有引用时先在引用中找。需要检索更多资料时，提示用户点「搜索本库」。回答带来源路径。用户可以就此结束，也可继续说「把这个结论记到周报」 |

## 2. 界面与一次完整交互

**独立右栏。** 按用户提供的 VS Code 截图，桌面工作区从左到右依次为目录、笔记列表、编辑区、助手对话栏。右栏从工作区顶部延伸到底部，使用与左栏一致的背景和分隔线。展开时编辑区让出右栏宽度，收起时这块空间归还编辑区。反向链接仍归文档信息面板管理。[工作区设计](笔记工作区设计.md)

**唯一开关。** 工作区右上角常驻一个右侧栏图标按钮。点击一次展开助手，再点一次收起。展开时图标高亮，辅助标签随状态显示「展开笔记助手」或「收起笔记助手」。空库、笔记列表和编辑笔记时都使用这个位置。开合保持当前笔记、光标、编辑器撤销记录、对话滚动位置、输入草稿及待应用修改。

```text
工作笔记库                                              [右侧栏开关]
目录       │ 笔记列表     │ 项目 / 周报.md         │ 笔记助手  [历史对话] [+]
项目       │ 周报.md      │                       │ 你：把联调改到周五。
会议       │ 联调纪要.md  │ 本周进展               │ 助手：修改预览
           │              │ 联调定于周三。         │ 原文：周三 → 改为：周五
           │              │                       │ [应用修改] [放弃]
           │              │                       │ ──────────────────
           │              │                       │ [继续对话……] [发送]
```

**对话栏内部。** 顶部显示「笔记助手」，中间的消息区独立滚动，底部固定输入区。用户消息靠右，助手回复、工具进度和文件修改预览按发生顺序出现在对话中。点击消息里的笔记路径可在编辑区打开对应笔记。切换文档、应用修改和点正文都保持栏位开合状态。

**历史对话。** 右栏默认显示当前会话的消息。建议在栏标题「笔记助手」右侧放一个时钟图标，标注「历史对话」，旁边的加号用于新建对话。点时钟后，同一栏列出当前笔记库的会话，按最后一条消息的时间倒序排列，每行显示会话标题和时间。标题默认取首条提问的开头。点一条即可回到该会话继续写。选「新对话」时原会话留在历史列表。桌面和手机沿用同一位置，工作区右上角的按钮仍是唯一的栏位开关。

**窄屏与手机。** 桌面窗口变窄时沿用工作区已有的目录和列表折叠规则。手机宽度一次容纳一栏，展开时将同一个对话栏作为当前可见栏，收起后回到原笔记或列表。右上角开关始终可用。键盘弹出时输入框随键盘上移，中文选字回车只确认候选字。

**对话状态。** 空会话按当前场景提供「整理成新笔记」「总结这篇」或「扩展这个分支」。无目标时可直接输入。生成时「发送」变为「停止」，状态行显示「正在查找周报」等实际工具动作。多个同名结果显示完整路径，选择后才继续。关闭面板收起会话。切库、注销或显式停止则终止后续工具调用。应用写入后，结果卡以真实回执显示「已同步」「已保存到本机，待同步」或「同步有冲突」，并给出「打开笔记」或对应的冲突入口。

**谁能看到资料。** 在「个人设置 → 笔记助手 → 本机模型」填写服务地址、模型 ID，按服务要求填写密钥。第一次在库内启用时显示实际模型服务、可访问的范围和编辑选项，并说明提问、前序对话及读到的笔记内容会发给该模型服务。会话默认用显式引用，打开某篇笔记只预选引用，发送或工具读取前可移除。提供「搜索本库」开关。关闭时只允许读取已引用文件，结果中也不暴露其他文件路径。库列表中的手动选笔记器在本地展示候选。缩小资料范围时开新上下文，防止前序对话把已移除的资料再次发送。

## 3. 如何把助手接到现有工具上

### 选择 Pi 的依据

两者都可以让桌面端在本机使用 MCP 和 Skill。选型取决于运行位置，以及用户想接的模型接口。

| 比较项 | Pi Agent Core | Codex |
| --- | --- | --- |
| 放进 WeNote | 在现有 TypeScript 前端里创建 Agent，模型适配层有浏览器入口。三个端可共用工具和预览代码。 | 官方 TypeScript SDK 要求 Node.js 18+。做桌面应用可由 Tauri 启动本机 `codex app-server` 并通过标准输入输出通信。普通网页无法启动这个进程，手机原生端也需要单独解决运行时集成。 |
| 在本机填模型 | 由应用选用对应的 Pi 协议适配器，同一个设置页可以接兼容的本地或远程端点。 | 可配置服务地址、模型和凭据，也支持 Ollama、LM Studio。本稿查阅的自定义 provider 配置要求 Responses 协议。仅提供 Chat Completions 的端点需要另做适配。 |
| 复用笔记能力 | 需要编写小型 MCP 工具适配层并载入内置 Skill。好处是 WeNote 能在调用真正的写工具前展示精确差异。 | 本地进程可使用现有桌面回环 MCP、发现 Skill、恢复会话及上报审批事件。嵌入时仍需把写入预览接到 MCP 执行之前，并管理各平台的进程分发和退出。 |

Web、桌面和手机需要共用一套助手交互，因此选定 Pi。写入结果以 WeNote MCP 回执为准。[Pi Agent Core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md) · [Pi 浏览器接入](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md#browser-usage) · [Codex SDK](https://developers.openai.com/codex/sdk/) · [Codex 应用集成](https://developers.openai.com/blog/codex-as-a-platform) · [Codex 模型配置](https://developers.openai.com/codex/config-reference/)

### 本机模型设置与连接

「接口协议」决定 Pi 如何向所填地址发送对话和工具调用。MCP 负责 WeNote 内部的笔记读写，所有模型共用同一个笔记工具入口。

| 模型接口选项 | Pi 1.6.1 标识 | 用户如何选择 |
| --- | --- | --- |
| OpenAI 兼容 · Chat Completions | `openai-completions` | 服务示例调用 `/chat/completions` 时选此项。例如本机 Ollama 可填写 `http://localhost:11434/v1` 和已安装的模型 ID，DeepSeek 的 OpenAI 兼容地址也使用这一项。[Ollama 官方示例](https://docs.ollama.com/api/openai-compatibility) · [DeepSeek 官方示例](https://api-docs.deepseek.com/) |
| OpenAI Responses | `openai-responses` | 服务示例调用 `/responses` 时选择 |
| Anthropic Messages | `anthropic-messages` | 使用 Claude 原生 Messages API，或服务商给出的 Anthropic 兼容地址时选择 |
| Google Gemini | `google-generative-ai` | 使用 Gemini Developer API 时选择。Vertex AI 单列为另一适配器 |

Pi 1.6.1 还列有 Azure OpenAI Responses、OpenAI Codex Responses、Amazon Bedrock Converse Stream、Google Vertex、Mistral Conversations 和 Pi Messages，共十种内置对话 API 类型。这里列的是 SDK 能力，WeNote 分端验收后再将相应选项标记为可用。[Pi 1.6.1 类型定义](https://github.com/earendil-works/pi/blob/v1.6.1/packages/ai/src/types.ts#L63-L75)

设置页提供「接口协议」「服务地址（Base URL）」「模型 ID」「API Key（可选）」和「测试连接」。首版建议支持 Chat Completions 与 Responses 两种协议。模型 ID 可手填，无需服务提供模型列表。测试使用一条无笔记的临时请求和一个无副作用的示例工具，分别报告服务可达、鉴权及模型能否调用工具。测试通过后才标为「可用于写笔记」。

地址、协议和模型 ID 保存在当前设备的应用设置中。建议网页密钥仅保留到当前页面会话结束，原生端提供「在此设备记住密钥」，使用系统凭据存储。变更服务地址后重新绑定密钥。用户填云端地址时，上下文发往该服务。填本机地址时，由本机模型服务推理。手机上的 `localhost` 指手机自身，连接电脑上的模型需填写手机可达的地址。

| 边界 | 建议实现 |
| --- | --- |
| Agent 运行时 | 在共享前端按需加载 `@earendil-works/pi-agent-core` 的 `Agent`。本稿核对了 npm 发布包 1.6.1 的类型定义。构造时注入 `streamFn`，凭据由宿主的 `getApiKey` 提供。`prompt` 开始一轮，`subscribe` 将文本增量和工具状态送给 UI，`abort` 停止。用 `AgentTool` 挂接授权工具，用 `toolExecution` 设为顺序执行，避免对同一篇笔记同时提出两个旧版本修改。[Pi Agent Core 官方说明](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md) |
| 模型连接 | 网页由浏览器直连配置地址，需满足站点 CSP、跨域及浏览器对本地网络和混合内容的限制。随客户端发布支持自定义 HTTPS 端点的连接策略，按浏览器能力验证可用的回环地址。请求只携带该模型凭据。受限时提示检查地址、CORS 或改用原生客户端。原生端由窄用途的 Tauri 请求桥流式连接本机配置的模型端点，将增量和停止信号接到 `streamFn`。两条路径都在设备上发起。[Pi 模型接入](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md) · [网页策略](../apps/web/index.html) · [原生策略](../apps/client/src-tauri/tauri.conf.json) |
| Skill | 构建时从仓库内置 `wenote-notes/SKILL.md` 正文，作为笔记任务的可信指令随请求加载。启用助手即可用，同一份源文件也供应外部助手。Skill 描述怎样定位目标和使用工具，写入仍须经过客户端预览和授权。笔记正文、导图备注、搜索结果以工具数据传入。[现有 Skill](../skills/wenote-notes/SKILL.md) |
| 客户端 MCP | 从 `useMcp` 抽出应用内连接的创建与撤销，给内置助手单独的连接 ID 和读写授权，绑定已有的服务地址、账号、库作用域。内置连接只在应用内注册。调用 `tools/list` 后将该连接发现的名称、说明和 schema 适配为 `AgentTool`，执行时走 `dispatch → Library.run`。保留现有的参数、权限、版本、草稿与幂等校验。从 MCP 的 `structuredContent` 构造工具结果，`isError` 和协议错误均进入失败分支。连接凭据留在宿主。[连接生命周期](../apps/web/src/mcp/Connections.tsx) · [协议分发](../apps/web/src/mcp/protocol.ts) · [笔记操作](../apps/web/src/mcp/library.ts) |
| 前端接线 | Web 和原生各自把当前库、目录、打开的笔记及导航回调传给同一个助手组件。点击发送时冻结引用的文件 ID 和目标目录，用户随后切换编辑标签时，待应用卡仍指向卡上原路径。成功后沿用 MCP 的 `changed` 回调刷新列表及干净的编辑器。[Web 入口](../apps/web/src/main.tsx) · [原生入口](../apps/web/src/desktop.tsx) |

**读取范围在宿主执行。** 按当前授权过滤工具。关闭「搜索本库」时收起 `search_notes`，逐次检查 `read_note`、`read_mindmap_nodes` 及已有文件写请求的 `file_id` 是否在引用集合中。只读授权可总结、讨论和显示草稿。用户要保存时，可就地为该助手开启当前库的编辑权限，再产生写入预览。授权变更、撤销或切库会使此前的待应用操作失效。

## 4. 从工具请求到可应用的草稿

| 助手动作 | 使用的 MCP 工具 | 操作卡内容 |
| --- | --- | --- |
| 查找、阅读和回答 | `search_notes`、`read_note`、`read_mindmap_nodes` | 显示实际读取的文件路径，按需展开记录。`cached_only` 为真时提示「仅搜索了本机缓存」 |
| 新建 Markdown、纯文本或导图 | `create_note` | 路径、格式、完整初稿或中心主题。改名、换目录或改稿后生成新的待应用参数 |
| 追加、局部修改、整篇重写 | `edit_note` | 按 `append`、`replace_text`、`replace_all` 展示新增文字、前后文或全文差异。清空全文时明确写「清空正文」 |
| 调整导图 | `edit_mindmap` | 按节点 ID 解析成可读的分支路径，区分添加、更新、移动、删除。删除子树列出后代数量，并呈现受影响的关联项。同一张图的一批操作一次应用 |
| 改名、移动、移入回收站 | `move_note`、`delete_note` | 给出源路径、目标路径或回收站去向。按钮直接写「移动」或「移入回收站」 |

1. **冻结提案。** 写工具的 `execute` 先在宿主生成不可变的待应用记录，包含作用域、连接 ID、工具名、完整参数和宿主分配的 `operation_id`。已有文件还要绑定 `file_id`、`base_path`、`base_version_id`。使用同版本内容和现有纯编辑函数在内存推演结果，直接从推演结果画卡片。此时只保存提案，工具尚未提交。[工具契约](../apps/web/src/mcp/tools.ts) · [文本和导图变换](../apps/web/src/mcp/content.ts)
2. **应用或继续改稿。** 点击「应用」才提交冻结的参数，提交前复核会话、授权和版本。点击「放弃」、停止或发送补充意见都会终止等待。补充意见连同上一版草稿进入下一轮，旧卡不能再应用。一个会话同一时刻只有一个活跃提案。跨文件任务逐篇确认并逐篇显示结果。中途取消时已完成的笔记仍可打开。
3. **保存与恢复。** 双击、超时或应用重启后核对同一逻辑操作时，使用同一连接、原参数和原 `operation_id`。回执丢失的卡显示「核对保存结果」。按原调用核对后再展示成功。`pending` 交给现有同步机制。若仅模型的收尾回复失败，已成功的结果卡仍显示真实路径和状态。[持久回执与队列](../apps/web/src/mcp/library.ts) · [跨窗口日志锁](../apps/web/src/mcp/journal.ts)
4. **并发与草稿。** `EDITOR_DIRTY` 时提供「返回笔记」，让用户处理编辑器里的草稿。`FILE_VERSION_CONFLICT` 时重读新版本，重新生成差异供用户决定。`TEXT_AMBIGUOUS` 时请用户选择带上下文的段落。新建重名 `PATH_CONFLICT` 时回到文件名输入。同步冲突引到该库已有的 MCP 冲突处理入口。

**会话存储。** 以服务地址、账号、笔记库和会话 ID 为键，在本机 IndexedDB 自动保存消息、引用、输入草稿及操作卡。每个库记住上次查看的会话，刷新网页或重启客户端后，从该库重新展开右栏即可接着聊。会话历史仅在当前设备查看。点击「新对话」开始新的上下文，设置里可清除本机对话。提案在发送 MCP 写请求前持久标记为「提交中」。启动时将其显示为待核对，未提交的预览仍需手动应用。恢复流程先在同一连接的 MCP 日志中查询回执，有回执就展示。日志也查不到时，提示用户选择「按原操作重试」。重试前复核同一授权。切库或登出时清空运行中的模型上下文和等待回调。模型网络中断可保留输入和已生成草稿。完整预览已在本机时，即使模型掉线，用户也可以应用，工具按本机条件返回同步状态。

## 5. 实施顺序与验收

| 阶段 | 可交付的用户路径 | 判定通过的观察结果 |
| --- | --- | --- |
| 0 · 本机配置 | 分别填写一个兼容的本机地址和一个自选 HTTPS 地址，以对应模型完成测试工具调用 | 记录实际出站目标，验证测试请求不含笔记，模型请求和密钥只发往所填端点。重启、清除配置及更换地址后核对凭据行为。网页跨域被拒或模型不支持工具时，显示对应原因 |

## 6. 待讨论的写入方式

**新建笔记要多快？** 本稿建议「创建笔记」前看一次草稿，已有笔记也逐次预览。如果日常最常用的是随手记一句，可对明确的「记下来」直接新建，结果卡提供打开及移入回收站。已有笔记继续预览。两种体验的差别集中在每天最常用的那一次点击。
