## 分类

| 类型 | 说明 |
| --- | --- |
| `feature` | 新功能、接口或用户能力 |
| `bugfix` | Bug 修复和回归处理 |
| `refactor` | 不改变外部行为的结构或性能调整 |
| `test` | 测试和验收基础设施 |
| `docs` | 产品、接口、开发和运维文档 |
| `chore` | 构建、依赖、脚本和工程维护 |

## 状态

| 状态 | 进入条件 | 离开条件 |
| --- | --- | --- |
| `PLANNED` | 需求已经登记 | 创建任务 worktree 并开始开发 |
| `IN_PROGRESS` | 已在任务 worktree 中工作 | 本轮测试、自审、提交并合入本地 `main`，或遇到阻塞 |
| `DELIVERED` | 本轮已合入本地 `main`，保留任务 worktree、分支和验收环境 | 用户确认、要求修改或放弃 |
| `CHANGES_REQUESTED` | 用户验收发现问题 | 在原 worktree 修复、测试、自审并再次合入 `main` 后回到 `DELIVERED` |
| `ACCEPTED` | 用户明确确认通过 | 清理原 worktree 和任务分支 |
| `MERGED` | 用户验收通过且任务 worktree、分支已清理 | 作为历史记录保留 |
| `BLOCKED` | 缺少必要决策或环境 | 阻塞解除后恢复 `IN_PROGRESS` |
| `ABANDONED` | 用户明确停止任务 | 作为历史记录保留 |

## 记录要求

每次新增任务至少记录以下内容。

- 任务 ID、类型、登记日期和一句话摘要
- 用户原始需求和可验证的验收条件
- 影响端和是否需要独立服务端
- 当前状态、分支、worktree 和任务记录路径
- 每轮自审结论、复测结果和交付提交号
- 用户验收结果
- 合并提交、清理时间和最终验证

状态变化按时间追加到对应任务记录，账本保留当前摘要。不要删除已经合并或放弃的历史记录。
