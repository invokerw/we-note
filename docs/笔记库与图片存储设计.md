# 笔记库与图片存储设计

设计已验收 · 2026-11-25 · 涉及服务端、Web、桌面和 Android。本文描述拟实现的行为。

## 一篇笔记的一张图

Markdown 图片地址统一使用 `{public-url}/assets/{用户ID}/{笔记库ID}/{年}/{月}/{日}/{16位图片标识}`。

用户、普通笔记库和加密笔记库在创建时分配 8 位小写字母数字 ID。数据库、同步接口、GM 存储目录和图片链接都使用同一组 ID。

假设 GM 把「在线内容」指向 `/srv/wenote`。用户 `k7m3p9wx` 的笔记库 `b4r8n2qy` 里有一篇 `周记.md`，笔记 ID 为 `n9`。用户在 2026 年 11 月 25 日插入 `白板.png`，服务端计算或复核原图的 SHA-256。存储路径中的 `{hash}` 代表完整 SHA-256，共 64 个十六进制字符。图片链接通常取摘要的前 16 个字符。同库同一 UTC 日期遇到前缀碰撞时，为后来的图片分配另一个固定的 16 位标识。重复上传相同内容复用其标识。日期取上传会话建立时的 UTC 日期。

| 从哪里看 | 审核示例 |
| --- | --- |
| GM 下的笔记库根目录 | `/srv/wenote/users/k7m3p9wx/vaults/b4r8n2qy/` |
| 当前正文 | `notes/n9/current.md`，相对于库根目录 |
| 笔记引用的图片 | `assets/2026/11/25/{hash}`，相对于库根目录 |
| 写入 Markdown 的内容 | `![白板](https://notes.example.com/assets/k7m3p9wx/b4r8n2qy/2026/11/25/9f3a72c1b84de605)` |
| API 实际收到的请求 | `GET /assets/k7m3p9wx/b4r8n2qy/2026/11/25/9f3a72c1b84de605`，由 `addr` 上的 `wenote-api` 处理 |

笔记库包含正文、版本和图片。编辑器保存公开源站下的绝对图片 URL。域名、磁盘目录和 S3 桶可以分别配置；改变 GM 存储位置时，Markdown 里的图片地址继续有效。

## 谁拥有这张图片

- **用户**取笔记库所有者的稳定 ID。协作者在同一篇笔记插图时，图片进入该库的 `assets/` 目录，实际上传者另记在上传记录中。这样协作者退出后，其他成员仍能阅读。
- **笔记库和笔记**使用现有库 ID 和文件 ID。文件树里的 `工作/周记.md` 是用户可见路径，重命名或在同一库内移动时只更新路径记录，图片链接继续有效。新建笔记首次插图前先持久化笔记 ID，原生端离线草稿保留本地图片，联网后确认笔记身份、上传成功，再提交带正式 URL 的版本。
- **图片复用**以库、UTC 日期和内容哈希为单位。同库同日上传相同内容，`assets/` 只存一份图片。库清单记录每个笔记版本引用的资源。同库复制笔记或粘贴图片链接时沿用原 URL，保存笔记版本时登记引用。跨库导入或粘贴时，服务端校验源资源读取权限和目标库写权限，将图片复制到目标库后写入目标 URL。目标对象已存在时直接复用。外部图片链接保持原文。

## GM 存储与版本

继续使用 GM「存储配置 → 用途分配 → 在线内容」选中的位置。本地以该目录为根，S3 以桶内配置的前缀为根，WebDAV 以配置目录为根。三者使用同一套相对路径。以 Markdown 为例，拟采用以下布局：

```text
users/{owner_id}/vaults/{vault_id}/
  manifest.json
  notes/{note_id}/
    current.md
    versions/{version_id}.md
  assets/{YYYY}/{MM}/{DD}/{sha256}
```

其他笔记格式沿用自身格式。库根目录的 `manifest.json` 记录库修订号、笔记 ID、逻辑路径、回收站状态、当前版本和历史版本，以及图片原名、类型、对象键和哈希。完整复制同一修订的库目录后，可以重建笔记树、正文、版本和图片。SQLite 管理在线查询、账户权限和设备同步状态。整站灾备同时保存数据库和内容存储。

版本文件先写入并完成校验，再以事务更新当前版本和图片引用。`current.md` 由已提交版本生成；中断恢复时按数据库的当前版本重建。正文读取以已提交版本为准。当前实现按库和内容哈希索引 Blob，新设计需要显式保存笔记、版本或图片对应的对象键，避免不同笔记的相同内容互相覆盖或被提前回收。GM 切换位置和备份恢复均按对象键枚举复制，读回复核大小和哈希后再切换；失败时可继续使用原位置。 库清单按已提交修订发布。复制或备份时固定修订号，在引用对象齐全并通过校验后交付。

## 一个服务入口，两种地址

`addr` 是 `wenote-api` 的实际监听地址。笔记读写、同步、图片上传和原图读取都挂在这个监听器上。`public-url` 是客户端能访问的源站，负责生成写入 Markdown 的绝对链接。部署方可让它直接指向 API，或通过代理保留请求路径并转发到 `addr`。服务端仍按会话和库权限读取原图，拥有链接的访客通过已有分享权限读取快照中授权的图片。

| 场景 | `addr` | `public-url` | 请求怎么到达同一进程 |
| --- | --- | --- | --- |
| 本机开发 | `127.0.0.1:8080` | `http://localhost:8080` | Web 和图片直接使用同一 HTTP 端口 |
| HTTPS 反向代理 | `127.0.0.1:8080` | `https://notes.example.com` | 代理接收 HTTPS，将原路径转给 `8080` |
| API 直接提供 HTTPS | `:8080`，已配置证书和私钥 | `https://notes.example.com:8080` | `wenote-api` 直接接收 TLS 请求 |

现有代码要求 `public-url` 为 HTTPS，且本地脚本的 `--port` 仅传给监听和邮件配置。拟让本机开发支持回环 HTTP，由脚本把选定端口同时用于监听和公开源站，例如 `--port 9080` 就生成 `http://localhost:9080/...`。跨设备使用可从其他设备访问的明确源站，通配监听地址 `:8080` 本身不足以推导这个域名。更换公开域名时，新内容使用新域名；已有 Markdown 中的绝对链接需保留旧域名转发或另行迁移。

## 图片访问权限与防盗链

Markdown 中的 `/assets/…` 是稳定地址。复制链接到外站后，即使读者在另一个标签页登录了 WeNote，外站也应无法嵌入原图。该约束同时覆盖新旧图片路由和分享页的图片接口。

| 读取入口 | 允许条件与处理方式 |
| --- | --- |
| 笔记预览 | Web 编辑器通过同源 API 携带登录令牌读图。服务端逐次检查库读取权限，成功后前端用临时 `blob:` 地址显示。Markdown 只保存正式地址。 |
| 分享页 | 使用该分享专属会话，逐次检查分享状态以及图片是否属于快照。分享撤销或到期后，后续图片请求即被拒绝。 |
| 桌面和 Android | 由原生客户端携带有效凭证访问配置的 WeNote 服务，执行同样的库授权检查。请求缺少浏览器来源头时仍须鉴权。 |

浏览器访问通过 `public-url` 的同源入口。图片接口不对其他源开放 CORS，也不反射请求的 `Origin`。对浏览器标记为跨源的资源请求（包括同站的其他子域或端口），在读取存储前拒绝；响应设置 `Cross-Origin-Resource-Policy: same-origin`，覆盖普通 `<img>` 嵌入。`Referer`、`Origin` 和 `Sec-Fetch-Site` 都不能代替身份与库权限。无凭证的 GET 或 HEAD 即使提交了看似正确的来源，也不能取得图片。

原图由鉴权接口返回，S3、WebDAV 和本地资源目录只供服务端读取。代理按相同规则转发新旧资源路由，遵守 `Cache-Control: private, no-store`，避免把一个用户的图片响应交给另一个用户。Markdown 和图片 URL 均不携带令牌。已授权读者可以保存或转发自己取得的副本；防盗链保护的是 WeNote 的在线资源入口。

## 上传、读取与删除

1. 编辑器从当前笔记发起上传，提交图片名、类型、字节数和 SHA-256。服务端从笔记查出库及所有者，验证编辑权限和图片内容类型，在该笔记下创建可重试的上传会话。图片白名单由三端共用，首选 PNG、JPEG、GIF、WebP；已有 SVG 按旧文件的受限方式下载。
2. 继续支持整图上传和分片续传。现有阈值为 4 MiB，分片为 1 MiB，单文件上限为 256 MiB。会话绑定目标笔记和首次建立日期，跨日续传复用同一地址。服务端核实最终长度、哈希和类型，将原图写入 GM 在线存储。客户端拿到完成响应，才向 Markdown 插入图片链接。
3. 读取 `/assets/` 下的新地址时，服务端先校验路径中的所有者与笔记库是否匹配，再验证库读取权限，从该库的 `assets/{年}/{月}/{日}/{SHA-256}` 读取图片。分享读取还须验证该图片属于获准访问的快照。桌面和 Android 缓存以库、笔记和图片标识区分，使用本地缓存显示离线预览。分享页面沿用可撤销的分享会话，不将用户登录凭证附在 URL 中。

## 无引用资源何时清理

沿用 GM 的笔记回收站保留期（当前默认 30 天）。图片从最后一个有效引用消失时开始单独计时，连续 **7 天** 无引用才允许后台删除。宽限期给撤销编辑、草稿保存和多设备同步留出时间。计时依据是引用状态，与图片路径里的上传日期无关。

| 用户操作 | 图片处理 |
| --- | --- |
| 笔记移入回收站或从中恢复 | 回收站笔记及其可恢复版本继续引用图片。恢复时原链接即可显示，保留期内不启动图片清理倒计时。 |
| 清空回收站，或笔记到期被彻底清除 | 在实际清除笔记及其版本后释放相应引用。如果这是最后一个引用，从此刻起算 7 天。手动清空与自动到期使用相同规则。 |
| 仅从正文移除图片，或删除共用图片的其中一篇笔记 | 其他笔记、可恢复的历史版本仍然能打开原图。若历史版本一直保留，它引用的图片也一直保留。 |
| 分享、导出或备份仍需读取原图 | 有效分享快照及尚在读取原图的任务持有引用。快照失效、任务结束或已经生成独立归档时释放相应引用。分享撤销立即停止分享访问。 |
| 图片上传完成，但用户关闭了未保存的草稿 | 从上传完成起给草稿 7 天。首次保存成功即登记版本引用，取消待清理状态。已上传的未完成分片沿用现有 24 小时续传规则。 |

**清理过程。** 在 SQLite 的同一事务中提交版本及资源引用的增删。最后一处引用消失时登记资源键和起始时间。重新引用立即取消倒计时，下次归零时重新计时。后台按同一库、日期和哈希复核当前引用及活动任务，与新引用写入互斥后才删除 GM 在线存储中的对象。已进入删除阶段的对象须等删除结束并重新确认或上传后才能被新版本引用。删除失败可重试，进程重启后继续，核验失败或迁移尚待核对的旧资源保留。读取图片或持有旧 URL 不会延长保留期，访问始终受原有权限约束。

按默认配置，一篇笔记进入回收站，30 天后实际清空，图片也只有这一篇笔记用过，则图片最早在入回收站约 37 天后由后台清理。如果另一篇笔记还在使用，图片随那篇笔记继续保留。

## 退出独立附件及迁移

拟关闭 Web、桌面和 Android 的通用附件上传、独立附件列表、仅附件导出、按附件创建新分享，以及 GM 中针对新图片的独立附件管理。编辑器提供「插入图片」。现有笔记文件上传、导入、分享和整库导出继续按笔记工作；便携 ZIP 在 `notes/` 存放正文，在同级 `assets/` 存放引用的图片。离线链接按正文在包内的位置生成相对路径。

| 现存数据 | 升级方式 |
| --- | --- |
| 旧 `/assets/{asset_id}` 和 `/assets/YYYY/MM/DD/{hash}` 图片 | 在库内扫描正文、历史版本、回收站和分享/导出快照，根据实际引用建立笔记归属。同库同日同哈希的图片迁入 `assets/` 一次，各笔记版本分别登记引用。冻结的版本保留原字节和哈希，通过有权限检查的旧路由解析；活动笔记可生成新版本来更新 URL。 |
| 旧 PDF、音视频、无引用或无法唯一归属的资源 | 列入迁移报告，保留原字节、原访问权限和已授权的历史下载入口。由管理员另行确认清理，迁移本身不删除这些文件。 |
| 已有端到端加密库 | 继续按库保存密文，笔记和图片的归属在客户端解密后处理。服务端从密文推导明文图片哈希或逐篇迁移在现有协议下不可行。若要为其引入逐图 URL，需独立设计加密协议。 |

迁移先生成按库清单和备份，再复制新对象、读回校验、登记映射，最后切换新写入接口。迁移期间应隔离该库写入或追平同步增量。每一阶段记录进度，重复执行可复用已校验对象。切换失败可回到旧配置和索引；切换后产生的新写入要先保全再回滚。旧客户端上传应得到明确的升级提示，已有分享链接、离线导出和历史版本列入兼容验收。

## 审核与验收

文档通过后，开发按以下场景编写失败测试，再实施服务端、迁移和客户端改动。

| 场景 | 验收结果 |
| --- | --- |
| 本地自定义端口及代理部署 | 在 `addr` 上验证笔记 API 与图片路由；用 Markdown 的完整 `public-url` 经直连或代理读到同一张图片。未授权访问被拒绝。 |
| Web、桌面、Android 在新笔记及已有笔记插图 | 得到 `/assets/{用户ID}/{笔记库ID}/{年}/{月}/{日}/{16位图片标识}` 地址，日期取 UTC。跨日续传、刷新重试和同库改名后仍能显示。 |
| 两个成员编辑同一笔记，两篇笔记插入相同图片 | 同库同日上传得到同一 URL，`assets/` 里只有一份图片，库清单可查到两篇笔记的引用。删除其中一篇后，另一篇及受保留的历史快照仍可预览。 |
| 登录用户在另一源的网页浏览被引用的图片 | 在独立域名及同站不同端口分别用浏览器嵌入笔记原图、旧图和分享图，并尝试跨源读取。外站无法显示或读取图片，同时同源笔记预览与已授权分享页可正常显示。 |
| 图片凭证与缓存隔离 | 无凭证、其他库账户、已撤销分享分别请求图片，均取不到原图。在代理后先用有权限账户读取同一 URL，再匿名请求，匿名请求仍被拒绝。原生客户端携有效凭证且无来源头可以读图。 |
| 验证无引用清理时点 | 用可控时钟覆盖移入回收站并恢复、主动清空、最后一个快照释放、未保存上传及宽限期内重新引用。验证 7 天边界，确认到期作业能重试，同时保存新版本不会产生断图。 |
| GM 在本地、S3、WebDAV 之间迁移，再做备份恢复 | 逐项验证正文、历史和图片哈希。已有链接无须改变，迁移中断能恢复。 |
| 从旧实例升级，或分享、导入、离线导出 | 旧图、冻结版本和已分享的非图片可读；导入副本在源笔记删除后仍能显示图片，离线 ZIP 可直接阅读。 |

**已确认的产品选择。** ① 路径中的用户取库所有者，实际上传者记入元数据。② “删除附件”指退出通用附件功能，旧非图片文件保留可读。③ 库目录自带清单，单独复制一致的库目录即可恢复笔记内容与目录树，整站备份还包含账户权限与设备同步状态。
