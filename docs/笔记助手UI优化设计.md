# 笔记助手 UI 优化设计

已确认设计 · 2026-11-27

首次使用时，用户从助手右上角打开「模型设置」，填入服务地址和可选 API Key。保存后回到原对话，在输入框旁选择这个服务提供的模型，再发送消息。下次打开助手时，输入区直接显示上次选用的模型。

首版仅支持 OpenAI 兼容协议，用户可填写 OpenAI 服务或 Sub2API 等兼容网关的地址。聊天接口可选 Responses 或 Chat Completions。

本稿细化原助手设计中的模型配置、模型选择和对话控件。界面沿用产品名称「笔记助手」。[原助手设计](客户端个人笔记助手设计.md) · [笔记库 UI 风格规范](笔记库UI风格规范.md) · [笔记库 UI 修复清单](笔记库UI修复清单.md)

## 助手展开后看到什么

```text
笔记助手             [历史] [+] [设置] [收起]
──────────────────────────────────────────
                      帮我把联调日期改到周五。
项目 / 周报.md
  原文　联调定于周三。
  改为　联调定于周五。
  [应用修改]  [放弃]
──────────────────────────────────────────
[引用笔记]  [周报.md ×]      □ 搜索本库
给笔记助手发消息…
[当前模型 · 默认 ▾]          [发送]
```

桌面沿用右栏，标题行与笔记标题对齐。手机沿用全宽助手，收起后回到原笔记或列表。消息区独立滚动，输入框和发送按钮留在底部。长模型名在工具栏截断，展开选择器可读到完整 ID。手机键盘弹出后仍能发送或停止。中文选字期间按回车只确认候选字。

| 区域 | 拟用组件和交互 |
| --- | --- |
| 消息区 | 采用 Ant Design X `Bubble.List` 展示用户和助手消息。回复按实际流式内容更新。文件路径、修改预览、应用按钮和同步回执由现有笔记操作卡渲染，保持发生顺序。 |
| 输入区 | 采用 X `Sender` 绑定当前会话草稿，底部放模型选择和发送。模型提供推理等级时，在同一浮层继续选档。生成中发送变为停止。已有待确认预览时，用户仍可输入补充意见并点「修改要求」。 |
| 设置与通用控件 | 使用笔记库主题下的 Ant Design `Modal`、`Form`、`Input.Password`、`Select` 和 `Button`。标题行图标提供可读名称，手机触控区沿用 48 × 48 CSS 像素。模型列表和设置弹窗跟随当前浅深色主题。 |

`Sender` 的受控输入、底部操作区和取消回调能接入现有对话流程；`Bubble.List` 可承载自定义消息内容。建议仅引入对话展示组件，消息生成、历史和写入确认继续使用现有 Pi 运行时。实施时在真实右栏验证组件样式和构建兼容性。[Sender 文档](https://x.ant.design/components/sender/) · [Bubble 文档](https://x.ant.design/components/bubble/)

## 右上角的模型设置

- 点击齿轮打开「模型设置」。首屏显示「服务地址」「API Key（可选）」和「在本机记住密钥」。服务地址的示例为 `http://localhost:11434/v1`。高级设置保留 Chat Completions 和 Responses 协议选择，已有用户回显保存过的协议。
- 填完地址即可保存。保存后关闭弹窗，回到原会话并开始获取模型。取消、Escape 或手机返回均丢弃本次表单修改，保留聊天草稿。地址格式错误时保持弹窗打开，在字段下方说明原因。
- 从旧版本升级时读取现有地址、协议、模型 ID 和本机凭据。更换服务地址立即清空表单中的旧 Key。本机记忆沿用现有按账号和地址绑定的存储。个人设置中移除重复表单，缺少 Key 等提示可直接打开助手内的设置。
- 现有「测试连接」用于验证所选模型能否调用笔记工具。建议把该操作放在输入区的模型选择菜单内，使用当前服务、协议和模型执行。获取模型列表成功只表示服务允许列举模型。测试结果就近显示，测试期间保留草稿。

## 自动获取和切换模型

首次打开已配置的助手、保存连接配置、或在模型菜单点「刷新列表」时，客户端向配置的 API 根地址追加 `/models` 发起 GET。比如 `https://gateway.example/team/v1/` 对应 `https://gateway.example/team/v1/models`。有 Key 时按当前地址附带 Bearer 凭据。此请求只读取目录，不携带对话或笔记。Web 使用浏览器请求，原生客户端扩展现有模型传输以支持这个 GET，继续按配置地址限制请求和重定向。服务端无需代理。

| 情形 | 输入框附近的反馈与操作 |
| --- | --- |
| 首次配置成功 | 按服务返回顺序列出 `data[].id`，忽略空 ID 并去重。只有一个选项时自动选用；有多个时提示「选择模型」。输入的草稿可继续编辑。 |
| 同一服务再次使用 | 回显上次所选模型。列表中找不到旧 ID 时标注「未在当前列表中」，由用户决定继续使用该 ID 或改选。 |
| 网关返回空列表或未提供目录接口 | 显示「暂无可选模型」或「此服务未提供模型列表」，提供刷新和手动输入模型 ID。兼容仅开放聊天接口的网关。 |
| 凭据、网络或跨域错误 | 显示可区分的原因。鉴权失败提供「打开模型设置」，网络或跨域错误提供「重试」。保留已保存的连接和当前草稿。 |
| 更换服务或切换模型 | 新服务单独获取列表，忽略旧请求迟到的响应。模型切换用于下一条消息，保留会话、引用和草稿。生成、等待写入确认或正在应用时锁定连接和模型切换，待本轮结束后恢复。 |

## 模型旁的推理等级

选择模型后，有明确档位时直接进入分档滑杆，入口同时显示模型名与当前等级。选「默认」时省略推理字段，由服务决定。若目录声明了默认值，可以显示「默认（low）」说明实际含义。缺少能力信息时只显示模型选择。更换服务、协议或模型时重新匹配能力，避免把上一个模型的档位带入下一次发送。

### Sub2API 的实测结果

2026-11-27 使用临时凭据对用户指定网关执行只读 GET。普通 `/v1/models` 返回 46 个模型，所有条目都有 `id` 和 `display_name`，均未列推理等级。在同一路径加 `?client_version=0.157.1` 得到另一种目录结构，38 个条目都包含 `supported_reasoning_levels`。同站的 `/backend-api/codex/models?client_version=0.157.1` 也返回了该结构。这个版本号是本次验证用值。实测范围为目录读取，逐档生成效果尚待实施验收。

| 目录中的模型 | `default_reasoning_level` | `supported_reasoning_levels[].effort` |
| --- | --- | --- |
| `gpt-5.4` | `medium` | `low`、`medium`、`high`、`xhigh` |
| `gpt-6.2-sol` | `low` | `low`、`medium`、`high`、`xhigh`、`max`、`ultra` |

先以普通目录填充模型选择器，再在同一配置地址的 `/models` 上带 `client_version` 获取补充信息。用扩展目录的 `models[].slug` 精确匹配普通目录的 `data[].id`，保留基础列表独有的模型。路径前缀和地址绑定沿用上一节规则。普通网关若忽略参数、拒绝扩展查询或返回空等级，模型选择和发送仍可用。切换账号、凭据或地址后丢弃旧能力结果。

在 WeNote 支持的两种协议中，Responses 将用户所选档位写入 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`。实施时检查实际出站请求，特别是网关声明的 `ultra` 等扩展值。客户端只提供能按原值发送的档位。若服务拒绝所选值，应保留输入并提供「改用默认」再发送，避免自动重放笔记工具调用。[OpenAI 推理参数](https://developers.openai.com/api/docs/guides/reasoning)

## 验收路径

1. **首次使用**　在空库展开助手，输入草稿，再打开「模型设置」。取消后草稿还在。重新打开并保存地址和 Key，自动出现模型列表。选择第二个模型发送，请求到达所填地址并使用该模型 ID。
2. **升级与换服务**　用上一版保存的配置打开助手，原模型可以继续使用。先请求慢服务 A，再改为服务 B。B 的选择器只显示 B 的模型，发送给 B 的请求中没有 A 的凭据。
3. **目录异常**　分别模拟 401、空列表、404 和跨域失败。检查提示、刷新、重新填写 Key 和手动输入路径。仅支持聊天的服务可以手动填 ID 完成对话。
4. **模型能力**　准备基础目录和部分覆盖它的扩展目录。核对完整模型列表、逐模型档位和默认值。检查设置中的接口选项仅有 Responses 和 Chat Completions，分别核对两种接口的实际出站字段，验证选定值原样到达网关。选择「默认」、切换到无能力信息的模型、扩展查询失败时，聊天请求均省略显式等级。工具能力通过单独的连接测试核验。
5. **笔记操作回归**　引用一篇笔记并要求修改，先补充要求，再应用预览。确认实际写入一次，结果路径可打开。切换历史会话后恢复草稿，发送期间可停止。
6. **布局与操作**　在桌面宽屏和手机宽度分别检查浅色与深色。用键盘打开和关闭选择器、弹窗并检查焦点。手机验证软键盘、长模型名和系统返回逐层关闭。原生客户端单列目录请求与交互的实际验证结果。

## 模型目录客户端版本

按设备本地日期，每天首次启动 Web 或本地笔记客户端时，从 npm 的 `@openai/codex` 稳定发布标签读取版本。当天重复启动复用缓存，获取失败时使用上次版本，首次离线使用已验证的内置版本。普通目录独立加载，扩展目录使用当次确认的版本。验收覆盖跨日、重复启动、超时及异常版本。

## 用 Ant Design X 调整一轮笔记对话

以「把发布清单里的验收日期改到周五」为例。用户要看清模型的建议、改了哪一句、什么时候真正写入。右栏空间优先留给原文与改后文字。助手的一轮回答从第一个增量起就占用同一个气泡位置，结束后就地显示结果和操作。用户向上核对旧消息时暂停自动跟随，滚回底部再恢复。`Bubble.List` 按轮显示流式正文、起草预览和运行状态，`Sender` 保留本轮草稿与模型选择。[现有聊天栏](../apps/web/src/assistant/Panel.tsx) · [组件总览](https://x.ant.design/components/overview-cn/)

| 用户看到的时机 | 组件与交互 |
| --- | --- |
| 打开空会话 | `Welcome` 用一句话说明可对当前笔记做什么。`Prompts` 根据上下文选两项，如「提炼这篇笔记的待办」「润色选中的段落」（后者仅在宿主能提供选区时显示）。点击将意图写进草稿并聚焦，发送仍由用户决定。未配置模型或未授权库时优先显示对应操作。 |
| 输入问题 | `Sender` 的 header 展示可移除的笔记引用，footer 放模型、可用推理档位和发送或停止。`Suggestion` 可供 `@` 唤起当前库的笔记候选，使用完整路径区分同名笔记，保留可点击的「引用笔记」入口。手机优先留出编辑和发送空间。 |
| 等待回答 | `Bubble` 显示等待状态。服务明确返回可展示的推理摘要后，在同一气泡中挂载 `Think`。生成时可展开阅读，正文开始后默认收起，尊重用户手动展开。选择 high 等档位本身不产生摘要。 |
| 处理笔记 | `ThoughtChain` 绑定实际的搜索、读取、起草、等待确认和保存结果。简单问答直接显示正文。多个工具步骤在已完成后折叠，待确认的文件路径、差异、应用和放弃始终可见。失败指向具体步骤，应用中的未知结果沿用原操作核对回执。 |
| 阅读结果 | `Bubble` 内使用现有 Markdown 渲染能力排标题、清单与代码。`Sources` 把本轮成功读取的笔记按文件去重列出，标为「本轮读取」，点击通过工作区打开。输出的修改单列目标路径和实际保存回执。 |
| 反馈 | 助手正文完成后，`Actions.Copy` 复制该条正文的 Markdown；`Actions.Feedback` 的有用/无用可切换、撤销，与消息一起保存在本机。用户只想改提法时，将原问题带回输入框由其编辑；涉及写入的上一轮需按现有确认流程重新预览。 |
| 查看历史 | 用 `Conversations` 复用当前库已有的会话和排序，标出活动项。留在同一侧栏内切换。草稿、确认预览和只读/编辑授权按原会话与库恢复。 |

**数据接入。** 为新消息分配稳定 ID 并绑定轮次。反馈、可见摘要、已读笔记和步骤状态都绑定所属轮次。已有历史按原有文本和提案渲染；旧记录无法还原的摘要或步骤留空。Responses 适配层可识别公开的 `response.reasoning_summary_text.delta`。Pi 的 `thinking_delta` 可以来自不同来源，渲染前应保留来源区别。兼容网关没有声明可展示摘要时，只用已知运行状态。保存成功取自 WeNote 回执。反馈元数据仅用于本机展示，不附加到后续模型请求。[现有事件订阅](../apps/web/src/assistant/turn.ts) · [会话数据](../apps/web/src/assistant/history.ts)

**通用及专项组件。** `XProvider` 继承笔记库的中文与深浅色主题。库内引用按文件 ID 和路径管理；以后支持从设备导入文件时再使用 `Attachments`。有可打开的输出文件时可用 `FileCard`，正文里的普通笔记引用用 `Sources`。系统通知、语音、文件夹视图、代码高亮和 Mermaid 展示按对应内容和操作需求引入。验收重点是首次引导、同一气泡中的流式回复、带真实来源的过程、可核对的保存结果和可恢复的反馈。[Think](https://x.ant.design/components/think-cn/) · [ThoughtChain](https://x.ant.design/components/thought-chain-cn/) · [Actions](https://x.ant.design/components/actions-cn/) · [Sources](https://x.ant.design/components/sources-cn/)

**验收场景。** 普通对话完成后只出现一份正文，评价后刷新仍可撤销。只读总结可以打开实际读取的笔记。带摘要的 Responses 与没有摘要的兼容响应都能完成；用户停止时显示已停止。修改笔记等待确认期间在窄栏和手机上均能核对原句与新句，放弃后原文仍在，重复点击应用只产生一次写入。试用样稿中的操作仅在示例数据上生效。

样稿的三个场景共用同一输入区。文本框下方用一个「模型 · 推理等级」按钮和右侧的发送按钮。打开先选模型，随即在同一浮层中选强度。当前等级居中显示，下方的模型名可返回模型列表。分档滑杆按服务声明的等级排列，右上角可恢复默认。换模型后使用新模型的默认档位，无可选等级时选完模型即关闭。关闭后入口回显组合，例如「6.2 Astra · 极高」。草稿随会话保留。
