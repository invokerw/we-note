# WeNote 文件插件开发规范

适用版本为插件 API `"1"`，包含本任务新增的可选文档操作接口。本文面向为 Web、桌面和 Android 客户端编写本地安装包的开发者。v1 插件负责把一种文件格式转换为可编辑的文本，并在用户保存时还原文件字节。宿主负责选择编辑器、显示文本、保存版本和导出文件。

## 1. 先跑通一个插件

仓库示例处理以 `WN1` 和一个 LF 开头的 `.txt`。打开时隐藏这四个字节，保存时写回标记。首次使用 SDK，在仓库根目录执行以下命令。已安装 `apps/web` 依赖时可跳过 `npm ci`。

```sh
cd apps/web
npm ci
node plugin-sdk/pack.mjs plugin-sdk/example /tmp/prefixed-text.zip
printf 'WN1\n初稿' > /tmp/prefixed.txt
```

1. 在「个人设置 → 编辑与插件 → 安装本地插件包」选择 `prefixed-text.zip`，核对插件名称、版本、来源文件名、适用扩展名、权限和包的 SHA-256，点击「授权并安装」。
2. 将 `prefixed.txt` 导入笔记库并打开，编辑区应只显示 `初稿`。改为 `定稿 abc`，点击右上角「英文转大写」，看到 `定稿 ABC` 后点击「保存」。重新打开仍显示 `定稿 ABC`。
3. 在标题栏的「文件操作」中点击「导出当前文件」，用普通文本编辑器打开副本，应读到两行 `WN1` 和 `定稿 ABC`。禁用插件后再打开笔记，默认文本编辑器也应显示这两行。

开发自己的插件时，复制示例目录，换用自己的 ID、扩展名和转换实现。打包器读取 `manifest.json` 和 `core.wat`，将 WAT 编译为 `core.wasm`。也可以使用其他工具链，只要生成的 ZIP 和模块满足下述契约。[示例清单](../apps/web/plugin-sdk/example/manifest.json) · [示例模块](../apps/web/plugin-sdk/example/core.wat) · [打包器](../apps/web/plugin-sdk/pack.mjs)

## 2. 安装包与清单

ZIP 根目录必须直接包含 UTF-8 编码的 `manifest.json` 和 `core.wasm`。压缩包大小和所有条目的声明展开大小之和均不得超过 512 KiB，最多 32 个条目。条目名称须唯一，使用相对路径，禁止空路径段、`.`、`..`、反斜杠、NUL 及 `__proto__`、`constructor`、`prototype` 路径段。v1 只加载清单指定的固定核心入口。[归档校验](../apps/web/src/plugins/archive.ts) · [安装校验](../apps/web/src/plugins/registry.ts)

```json
{
  "id": "org.example.prefixed-text",
  "name": "带标记的文本",
  "version": "1.0.0",
  "api_version": "1",
  "file_extensions": [".txt"],
  "capabilities": ["parse", "edit", "serialize", "export"],
  "mcp_model": "text",
  "actions": [{ "id": "uppercase", "label": "英文转大写", "kind": "edit" }],
  "entry": { "core": "core.wasm" }
}
```

| 字段 | v1 要求 |
| --- | --- |
| `mcp_model` | 新增文件格式须支持 MCP 增删改查。UTF-8 文本使用 `text`，提供原生导图数据模型的插件使用 `mindmap`，同时声明 `parse`、`edit`、`serialize`。既有插件可继续使用旧清单。 |
| `id` | 至少两段，以点分隔。每段以小写英文字母开头，其余字符限小写字母、数字和连字符。`com.wenote.` 前缀由宿主保留。发布新版沿用原 ID。 |
| `name` | 安装确认页显示的名称，去除首尾空白后须非空。 |
| `version` / `api_version` | 插件版本为三段数字字符串，如 `"1.2.0"`。宿主 API 版本固定为字符串 `"1"`。 |
| `file_extensions` | 非空数组。单后缀以点开头，首字符为小写字母或数字，其后可含小写字母、数字、`_`、`-`。支持的复合后缀只有 `.mind.json`。 |
| `capabilities` | `parse` 必填。可编辑插件须同时声明 `edit` 和 `serialize`。需要「导出当前文件」时再声明 `export`。未知权限会使安装失败。 |
| `actions` | 可选。按显示顺序列出当前文件的专用按钮，见下节。省略时保留原有打开、保存和导出行为。 |
| `entry.core` | 必填，值固定为 `core.wasm`。 |

只读查看器可只声明 `["parse"]`。宿主将正文设为只读，提供原文件下载。`export` 控制导出当前结果的按钮，无需实现名为 `export` 的 WASM 函数。[编辑与导出实现](../apps/web/src/plugins/PluginEditor.tsx)

## 3. 右侧文档区和标题栏按钮

插件的作用域是用户当前打开的本地文件。标题栏由宿主绘制。固定操作从左到右依次为 **保存、加星、分享、反向链接、更多**。插件按钮和编辑模式位于固定操作左侧。手机沿用同一顺序，按平台能力和文档状态省略不可用项，其余按钮保持相对次序。在宽度不超过 400 CSS 像素的手机上，若有文件专用操作，操作组在文件名下方单独一行靠右显示。

| 操作 | 谁提供、何时出现 |
| --- | --- |
| 保存 | 宿主统一处理保存及快捷键。可编辑文件打开后显示，内容未改时显示「已保存」。只读、打开失败和历史查看状态收起保存入口。手机上普通文本可通过「完成」提交。 |
| 加星 | 宿主管理笔记标记，和正文编辑权限无关。账号或笔记库标识未就绪时禁用。 |
| 分享 | 宿主按平台能力提供。Web 分享已保存版本，有草稿时用户选择如何处理；Android 的系统文本分享适用于宿主支持的文本笔记，手机从标题栏直接进入。桌面本地库和 Android 的 WASM 文件沿用各自可用的导出入口。 |
| 反向链接 | 打开或收起笔记信息面板，查看链接到本笔记的文件。展开时正文占满剩余空间。 |
| 更多 | 固定在最右侧，收纳历史版本、下载原文件等宿主操作。 |
| 文件专用操作 | 插件按格式声明，如英文转大写、查看文本统计。保存、加星、分享等通用操作留给宿主，按钮文案应点明实际效果。Markdown 的模式选择和导图的画布操作属于具体编辑器。 |

**空间。** “全屏”指右侧文档面板：标题栏留在顶部，正文占满其下全部可用宽高。空文件、只读文件和错误视图使用同一块区域。正文可以有文字内边距，由正文自己滚动。目录、笔记列表和用户主动打开的信息面板仍可使用。宽面板直接显示第一个专用操作，其余收进「文件操作」。文档面板宽度不超过 640 CSS 像素时，第一项也进入该菜单。按钮顺序由清单数组决定。

**亮暗主题。** 宿主按当前生效主题绘制正文、背景、光标、选区、按钮与焦点，包含跟随系统和定时切换。主题属于显示状态，切换时原地更新，保留正文、草稿和光标。WASM 接收的文本与主题无关，插件无需实现主题回调。宿主布局和颜色见[文档区样式](../apps/web/src/workspace.css)。

### 声明并执行一个按钮

`actions` 的每项包含 `id`、`label` 和 `kind`。`id` 在本插件内唯一，匹配 `^[a-z][a-z0-9_]*$`；`label` 为非空的可读文本。每个声明都须有同名规则的 WASM 导出，安装时即检查。例如 `uppercase` 对应 `action_uppercase(i32 ptr, i32 len) -> i64`，内存和超时与 `open` 相同。

| `kind` | 当前正文输入与结果处理 |
| --- | --- |
| `edit` | 需要 `edit` 和 `serialize`。以 UTF-8 传入屏幕上完整的当前草稿（LF 换行，宿主已分离文件开头的 BOM）。返回完整的新编辑文本，替换草稿，用户点击「保存」才写文件。 |
| `message` | `parse` 足够。输入与 `edit` 相同，返回一段 UTF-8 文本，由宿主作为状态消息显示，正文和已保存文件保持原值。 |

返回文本须能按 UTF-8 解码且不含 NUL。执行期间宿主锁定编辑，插件报错时保留草稿。切换文件后，旧文件的命令与结果退出当前视图。选择可安装包提供的命令时，宿主只调用清单中声明的导出。旧包可省略 `actions`；旧宿主会忽略该字段，作者应保留基本打开和保存路径。[清单与调用接口](../apps/web/src/plugins/registry.ts) · [正文与按钮实现](../apps/web/src/plugins/PluginEditor.tsx)

## 4. WASM 调用契约

| 导出函数 | 输入 | 成功输出 |
| --- | --- | --- |
| `open(i32 ptr, i32 len) -> i64` | 当前文件的完整原始字节 | 严格有效且不含 NUL 的 UTF-8 编辑文本。所有插件必须实现。 |
| `serialize(i32 ptr, i32 len) -> i64` | 编辑后的完整 UTF-8 文本 | 要写回原文件的完整字节。声明 `serialize` 时必须实现。 |

- **内存和返回值。** 模块唯一导入为 `env.memory`，推荐直接使用示例的 `(memory 512 512)` 声明。宿主提供固定 32 MiB 线性内存，从地址 `0` 写入输入，长度以字节计。结果打包为 `(u64(offset) << 32) | u64(length)`，高 32 位为无符号地址，低 32 位为字节数。允许复用输入区；长度为零表示空输出，也是有效结果。
- **资源限制。** 每次调用的输入和输出各限 16 MiB，输出区必须完全位于内存内。每次调用在独立 Worker 和新 WASM 实例中执行，宿主在 2.5 秒超时后终止 Worker。模块不得定义私有表、私有内存、启动函数或异常标签。宿主没有提供 WASI、网络、凭据、其他文件或原生桥接接口。
- **无跨调用状态。** `serialize` 只能从本次传入的文本重建文件。示例能写回 `WN1\n`，因为它是格式常量。若文件含每份文档各自不同的元数据，要把重建所需的信息保留在编辑文本中。无法完整还原时，建议先提供只读插件。
- **错误处理。** `open` 应自行检查格式标记和结构，无法处理时可触发 WASM trap。宿主显示错误并保留「下载原文件」。序列化失败时宿主提示错误，保留草稿。安装检查会编译、实例化并检查所需函数是否存在，函数签名及返回数据仍需用真实样本验证。[Worker 实现](../apps/web/src/plugins/wasm.worker.ts) · [调用与超时](../apps/web/src/plugins/registry.ts)

## 5. 匹配、保存与升级

**选择编辑器。** 宿主将文件名转为小写，先识别 `.mind.json`，其余文件取最后一个扩展名。在该扩展名上，已启用的本地插件优先，其次为内置 Markdown（`.md`）或 Mind Elixir（`.mind.json`），最后使用始终启用的默认文本编辑器。普通 `.json`、无扩展名文本等都可由默认编辑器打开。匹配依据是后缀，同一后缀下解析失败会显示错误，不会再试下一个插件。例如安装示例后，普通 `.txt` 缺少 `WN1\n` 也会进入示例插件并报错。因此专用格式宜选择专用后缀。[注册表](../apps/web/src/plugins/registry.ts) · [默认编辑器验收记录](tasks/FEAT-20261126-default-text-editor.md)

**保存与导出。** 宿主编辑时隐藏文本开头的 BOM，统一用 LF 显示换行，提交给 `serialize` 前按原文本记录恢复 BOM 和行尾。文本与上次保存内容相同时，导出直接复用已保存的字节。编辑后导出和保存使用同一序列化结果，导出只生成副本。Web 保存由宿主携带基础版本提交，桌面和 Android 由宿主写入本地库。为新后缀设计磁盘格式时，还应核对服务端写入规则，例如 `.csv` 或 `.foo` 必须是合法且不含 NUL 的 UTF-8；插件清单只决定打开方式。[文本往返](../apps/web/src/markdown/textFile.ts) · [服务端文件规则](../services/api/internal/store/file_write.go)

**安装与升级。** 包及启用状态保存在当前浏览器或客户端的本地配置中，其他设备需分别安装。同 ID 包重新授权后替换旧包并启用，宿主按 ID 替换，不比较版本高低。不同本地插件声明了相同后缀时安装会失败，即使原插件已禁用也须先卸载。运行前宿主核对 ID、包哈希及启用状态；遇到「此插件已禁用或更新」提示时应重新打开文件。[插件管理界面](../apps/web/src/plugins/Manager.tsx) · [安装与调用检查](../apps/web/src/plugins/registry.ts)

## 6. 发布前如何验收

建议为插件保留一个可编辑样本、一个旧版本样本和一个格式错误样本。验收时同时检查界面显示和实际文件字节。

| 场景 | 可观察的通过条件 |
| --- | --- |
| 打开、保存、重开 | 未修改时导出与原件逐字节一致。修改一个字段并保存，重开看到新值，未修改字段及格式标记仍在。文本格式按其约定覆盖中文、空正文、BOM 和 CRLF。 |
| 错误与边界 | 截断或标记错误的文件显示错误，仍可下载完整原件。编辑后不能序列化时，原文件和草稿可恢复。对接近大小上限的样本，检查转换后的输出长度。 |
| 权限与生命周期 | 只读包无法编辑或保存。用同 ID 新包替换并重新打开旧样本。禁用或卸载后重新打开，验证对应的内置编辑器或默认编辑器接手。 |
| 声明支持的平台 | Web 比对保存后的服务端内容。桌面、Android 比对本地保存后重开的内容；若声明支持同步，再在另一设备检查字节和打开结果。 |

在 `apps/web` 可运行 `node --test tests/default-editor.test.mjs` 核对匹配和回退。浏览器用例需要本机 Chrome 和允许注册测试账号的独立 WeNote 测试服务；将 `WENOTE_TEST_ORIGIN` 设为该服务地址后运行 `node tests/phase4.mjs`。该脚本会创建测试账号和笔记库，验证示例安装、只读权限、编辑保存、重载和禁用回退。自有格式的往返样本需要单独验证。[匹配测试](../apps/web/tests/default-editor.test.mjs) · [浏览器验收](../apps/web/tests/phase4.mjs) · [Android 离线插件用例](../apps/web/tests/android.mjs)
