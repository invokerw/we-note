## 第一轮 · 修复离线同步和未保存提醒

| 场景 | 基线观察 | 验收条件 |
| --- | --- | --- |
| 旧版本清理后重新联网 | 两台设备从同一版本开始。B 离线编辑，A 连续更新同一笔记 13 次。服务端清理历史后，B 连续两次同步返回 404，后续笔记无法继续同步。 | B 保留可打开的本地冲突副本，原路径呈现远端正文，同轮继续同步其他笔记。重复同步保留两端内容且不会重复生成副本。临时网络错误仍可重试。 |
| 已有 Markdown 离线插图 | A 给已同步的笔记添加本机暂存的 PNG，重新联网后，两端同步成功，但 B 收到的正文仍使用临时图片地址，无法读取图片。原有测试覆盖新建笔记。 | 正文使用正式资源地址，B 在没有 A 的缓存时也能读取原图，并核对字节。覆盖已有笔记和新建笔记，以及上传失败后重试。 |
| Web 重命名取消或失败 | 输入未保存文字，点「移动或重命名」，确认后取消路径输入。草稿仍在屏幕上，页面已解除关闭提醒。 | 取消输入或请求失败后，正文、保存按钮和离开提醒一致；成功重命名后按用户选择切换。 |

## 第二轮 · 恢复网页草稿

- [ ] 网页 Markdown 和默认文本编辑器在编辑时将草稿持久化，按账号、库和文件标识隔离，记录所依据的服务端版本。
- [ ] 模拟页面意外关闭，重开同篇时能恢复输入或明确放弃草稿；恢复的文字仍需由用户保存到服务端。
- [ ] 如果另一设备已提交新版本，用户能核对远端正文与本地草稿。保存成功后清理已提交的草稿，保存失败或保存期间继续输入时保留最新编辑。

## 第三轮 · 管理同步冲突

- [ ] 桌面和 Android 用户能从笔记库重新打开待处理冲突。下一次同步和重启后，仍能找到原笔记与冲突副本。
- [ ] 文本笔记支持对照本地与远端的差异，选择一方或编辑合并结果。窄屏能切换查看两个版本。
- [ ] 成功保存后可标记已处理；保存失败、原文件再次变化或取消操作时保留两份正文和待处理记录。

## 第四轮 · 大笔记库增量同步

- [ ] 用可重复生成的 1,000 篇和 10,000 篇笔记，在相同环境比较首次同步、零改动同步和仅修改一篇时的耗时、本地正文读取量和网络传输量；记录样本大小、重复次数及测量方式。
- [ ] 根据基线读数选择先优化本地扫描还是远端清单。远端可利用现有变更接口，本地可避免重复读取未变正文。在同等输入下记录优化前后的实际变化。
- [ ] 验证旧客户端状态升级、游标失效后全量恢复、文件移动和删除、同一路径再次编辑及中断重试。用两端文件路径和内容哈希检查同步结果。
