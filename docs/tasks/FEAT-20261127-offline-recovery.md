### 同步性能实测

`python3 tests/performance/sync.py` 使用 macOS ARM64 本地文件系统、同一台机器的回环协议夹具与真实 Rust 同步器。每篇 4,096 字节，首次绑定前本地和远端已有相同文件。空闲同步重复三次取中位数，首次绑定及远端修改一篇各测一次。耗时单位为毫秒，传输量仅统计 HTTP 请求与响应体。扫描读取量专指生成本地文件哈希的正文读取，文件属性、状态文件、下载校验读写另计。

| 笔记数 | 场景 | 耗时（优化前 → 后） | HTTP 字节（前 → 后） | 扫描正文字节（前 → 后） |
| --- | --- | --- | --- | --- |
| 1,000 | 首次绑定 | 6,442 → 183 | 178,964 → 178,964 | 4,096,000 → 4,096,000 |
| 1,000 | 空闲 | 131 → 25 | 178,926 → 208 | 4,096,000 → 0 |
| 1,000 | 远端修改一篇 | 143 → 34 | 183,022 → 4,501 | 4,096,000 → 0 |
| 10,000 | 首次绑定 | 155,479 → 1,276 | 1,798,965 → 1,798,965 | 40,960,000 → 40,960,000 |
| 10,000 | 空闲 | 1,303 → 180 | 1,798,927 → 211 | 40,960,000 → 0 |
| 10,000 | 远端修改一篇 | 1,334 → 211 | 1,803,023 → 4,505 | 40,960,000 → 0 |

小数据集 `python3 tests/performance/sync.py 100` 在改动前命中「空闲仍获取全量清单」断言，退出 1。实现后退出 0，同时验证了过期游标获取完整清单。首次绑定批量登记已匹配文件。后续先拉取连续变更，游标过期或响应不连续时回退。macOS、Android 等 Unix 文件系统依据设备号、inode、文件大小、修改时间和状态变更时间复用哈希，粗粒度时间戳回退到读取正文。Windows 使用增量网络拉取，本地扫描继续逐文件校验。未对真实手机或广域网进行性能外推。
