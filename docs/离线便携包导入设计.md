# 个人设置中的导出/导入

需求已确认 · 2026-11-26

将「头像 → 个人设置」中的「导出」改名为「导出/导入」。页首显示当前笔记库名称，下方依次展示导出区和导入区。迁移笔记时，在旧库导出离线便携 ZIP，再打开新库，在同一设置项中导入。即使旧服务器已关停，也能凭 ZIP 完成迁移。

## 页面布局

- **导出区**提供「仅笔记」和「完整笔记库」两种范围。选完整库时可选「保留在线链接」或「离线便携（使用包内图片）」。点「创建导出」打包，在导出记录中点「下载 ZIP」。
- **导入区**提供「选择 ZIP」按钮，校验成功后自动打开「导入预览」弹窗。导入完成后回到本页查看结果。手机也按导出在上、导入在下排列，向下滚动即可操作。

## 导入操作

| 步骤 | 页面和行为 |
| --- | --- |
| 选择文件 | 在导入区点「选择 ZIP」，直接选择完整笔记库的离线便携包，无需解压。 |
| 预览 | 弹窗列出包的导出时间、笔记数、资源文件数、目标目录，以及有冲突的路径。可展开查看笔记目录。例如「导入到『工作笔记』，共 12 篇笔记、8 个资源文件」。点「取消导入」丢弃这次暂存并返回设置。 |
| 确认导入 | 点弹窗底部的「确认导入」后显示进度。目标目录有变化时，在原弹窗展示新目录并等待再次确认。若要使用单独的导入目录，按钮旁先展示完整目录名。关闭设置后仍可回来查看已确认的任务。 |
| 查看结果 | 导入区显示实际导入数量和目标位置。点「查看笔记」进入对应目录。网页刷新文件列表，桌面和 Android 通过现有同步流程拉取新内容。关闭设置回到原笔记时保留编辑中的草稿。 |

建议网页、桌面和 Android 首版共用以上流程。导入由目标库的服务端执行，需要联网、登录并拥有该库的写权限。客户端离线时在入口说明「连接服务器后可导入」。用户持有其他账号或其他实例导出的包，也可导入自己有写权限的库。

## 笔记放在哪里

默认按原路径写入当前库。包里的 `notes/项目/周报.md` 在库中显示为 `项目/周报.md`。`notes/` 是打包用的外层目录。普通文本、思维导图和其他笔记文件都随包导入，每份文件在目标库拥有新的文件 ID 和初始版本。可恢复的范围是导出时的文件内容和目录结构，历史版本、回收站、分享和账户设置均在包的范围之外。

**遇到同名，建议保留两份。** 只要有一处目标路径已被占用，预览就列出冲突，并建议把整批放进一个新目录，例如 `导入 2026-11-26/`。目录名已被使用时递增编号。用户可接受该目录或取消。这样已有周报继续留在原处，包内两篇笔记之间的相对路径也仍然有效。文件与目录同名、仅大小写不同等情况按各端都可同步的路径规则判定。如果确认前另一台设备占用了目标路径，返回更新后的预览供用户再次确认。

## 图片如何跟着笔记迁移

例如，归档中的 `notes/项目/周报.md` 通过 `../../assets/2026/11/25/<哈希>` 引用截图。导入时先以这篇笔记在 ZIP 中的位置找到图片，再把包里的实际图片写入目标库，将正文中这处链接改成目标库生成的资源地址。图片归目标库管理，从另一台设备打开笔记也能看到。两篇笔记共用同一张图时，复用目标资源，并分别登记引用。

- 读取资源清单中的全部文件，包括导出包携带的旧附件。引用 PDF 等旧附件的笔记可以从链接打开该文件。预览单列未被笔记引用的资源数量，导入后沿用目标库的资源保留规则。
- Markdown 按链接语法识别图片、附件链接和引用式链接，保留标题、查询参数与锚点。代码块、行内代码、示例文本和外部网址按原文保存。笔记间的相对链接沿用原目录结构。整批改放新目录时，对可明确指向包内笔记的库根路径链接同步更新；目标有歧义的链接在预览中列出，交给用户核对。
- `.mind.json` 等非 Markdown 文件按原始字节写入。包中旧库的用户、笔记、版本和资源标识用于读清单，目标库自行建立身份与访问权限。

## 包校验与失败处理

沿用现有导出格式。服务端读取 `manifest.json`，确认 `scope=all`、`mode=portable`、`layout=notes-assets`，再核对 `asset-manifest.json`、`checksums.sha256` 和实际条目。Markdown 便携副本可能已改写，校验使用导出副本的 `content_hash`。资源清单中多条记录可合法指向同一个包内文件。格式依据见[导出打包实现](../services/api/internal/store/export_archive.go)和[便携链接转换用例](../services/api/internal/store/portable_markdown_test.go)。

| 情况 | 用户看到的结果 |
| --- | --- |
| 选择了仅笔记包、保留在线链接的包或普通 ZIP | 提示「请选择 WeNote 的完整笔记库离线便携包」，并显示对应导出选项。 |
| 缺少清单、正文、资源文件，或文件与校验值不符 | 预览指出出错的条目，本次导入结束。可以重新选择完整包。 |
| 条目含越界路径、重复 ZIP 文件名，或解压数据超出服务端限制 | 在暂存阶段拒绝该包，说明原因。服务端按实际读取量限制单项、总量和条目数。 |
| 上传中断、空间不足或导入期间失去写权限 | 显示失败阶段及原因。已上传的数据先暂存，确认时再次检查权限、路径和容量。笔记版本、资源引用和同步记录整批提交，失败时清理暂存数据。 |
| 连点确认、确认后断网或客户端重启 | 同一任务只提交一次。重新打开「导出/导入」可在导入区查到结果。再次主动选择同一个包时，预览提示该库此前的成功导入时间及目录，由用户决定是否另存一份。 |

## 验收场景

1. 在库 A 创建两篇分属不同目录且共用截图的笔记，再加一份思维导图。从「导出/导入」的导出区生成并下载便携 ZIP。关闭源服务，在另一实例的空库 B 导入。核对两篇笔记的路径、导图内容、截图显示，以及另一个客户端同步后的结果。
2. 在 B 预先创建内容不同的 `项目/周报.md`。预览中看到冲突和实际目标目录。取消后 B 仍只有原周报；重新确认后两份周报均可打开，导入笔记间的相对链接指向导入的那一份。
3. 用含中文目录、引用式图片、旧附件、外网链接和代码块的包导入。检查库内资源可打开、代码示例保留原文。再从 B 导出便携包，断网解压后，笔记里的图片仍能显示。
4. 分别使用在线链接包、缺一张图片的便携包、校验值错误的包和只读账号。每次得到具体提示，目标库文件数与操作前一致。
5. 在预览后制造路径冲突，确认页面展示新目录。模拟提交中断、重试以及确认后关闭客户端，检查任务只有一个结果，其他设备同步时只看到完整的导入结果。
6. 在网页、桌面和 Android 分别打开「个人设置 → 导出/导入」，核对页首的当前库名称。在同一页完成创建导出、下载 ZIP、选择 ZIP、预览、取消、重新选择、确认导入和查看结果。桌面或手机断网时入口说明联网要求，返回编辑器后可继续原草稿。
