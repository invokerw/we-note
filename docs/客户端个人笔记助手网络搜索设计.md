# 客户端个人笔记助手网络搜索设计

开发设计稿 · 2026-11-28 · 对应任务 `FEAT-20261128-pi-web-access`

## 1. 目标

在 WeNote 个人笔记助手中增加网络搜索能力。Agent 继续使用 Pi Agent Core，网络搜索通过 `pi-web-access` MCP 提供，搜索提供商使用 OpenAI Responses API 的 `web_search`。

当前验证过的模型服务配置如下。

- Base URL：`https://api.ergou.vip/v1`
- Responses endpoint：`https://api.ergou.vip/v1/responses`
- 已验证模型：`gpt-6.2-sol`
- 搜索工具：`web_search`

API Key 只在本机配置或 Gateway 运行环境中保存，不进入仓库、任务记录和日志。

## 2. 方案边界

### 2.1 运行链路

```text
WeNote Pi Agent Core
    ↓ AgentTool 适配
pi-web-access MCP
    ↓ OpenAI provider
OpenAI-compatible Responses endpoint
    ↓ native web_search
搜索结果与来源
```

WeNote 负责 Agent 循环、笔记 MCP、权限、搜索状态和来源展示。`pi-web-access` 负责搜索工具编排、网页内容获取和来源结果。OpenAI 负责执行搜索。

### 2.2 首轮范围

- 从 `pi-web-access` 获取并注册搜索相关 MCP 工具
- 接入 `web_search` 和可用的网页内容读取工具
- 使用 OpenAI Responses provider
- 支持桌面端本地 MCP 进程或已配置的 Gateway
- 支持 Web 和移动端使用 HTTPS MCP Gateway
- 搜索开关、状态提示、来源链接和失败提示
- 搜索结果不直接触发笔记写入
- 继续使用现有笔记读取和写入预览流程

### 2.3 明确排除

- 不把 API Key 写入代码、文档或提交
- 不把笔记正文自动拼接到网络搜索词
- 不把搜索结果写入笔记，除非用户另行要求并确认写入
- 不在首轮接入图片搜索、视频搜索和多搜索提供商自动回退
- 不依赖 ChatGPT 网页登录态，使用配置的 API Key 和 Responses endpoint

## 3. 配置设计

### 3.1 用户侧配置

设置页增加网络搜索配置。

- 是否允许联网搜索
- 是否填写 Web Access MCP Gateway 地址
- OpenAI-compatible Responses Base URL
- 搜索模型 ID
- API Key

默认关闭联网搜索。启用后，只有当前会话会注册网络工具。

### 3.2 运行时配置

`pi-web-access` 的配置由宿主生成或注入运行环境。示意配置如下，字段名称以实际安装版本的工具说明和 `tools/list` 结果为准。

```json
{
  "provider": "openai",
  "openaiApiKey": "$OPENAI_API_KEY",
  "openaiResponsesUrl": "https://api.ergou.vip/v1/responses",
  "openaiSearchModel": "gpt-6.2-sol"
}
```

WeNote 不复用用户机器上的全局 Pi 配置作为唯一来源。桌面端启动本地进程时传入当前助手配置。桌面端本地模式由宿主进程生成临时配置，并通过子进程环境变量注入 API Key。Gateway 模式将当前 API Key 作为可选 Bearer 凭据发送，Gateway 也可以忽略该请求头并在服务端保存自己的 OpenAI Key。

## 4. 工具接入

### 4.1 MCP 客户端

新增 `WebAccessClient`，负责以下协议操作。

1. 建立 MCP 会话
2. 调用 `initialize`
3. 调用 `tools/list`
4. 将允许的工具转换为 Pi `AgentTool`
5. 通过 `tools/call` 转发调用
6. 支持 AbortSignal、60 秒请求超时和连接关闭

搜索工具名称、参数 schema 和结果结构以运行时 `tools/list` 为准。适配层不硬编码提供商专属参数，只负责协议转发和结果归一化。

### 4.2 Agent 接入

当前 `runTurn` 已经把 WeNote MCP 工具转换为 `AgentTool`。本任务在同一处合并网络工具。

```text
WeNote tools + Web Access tools → Agent.initialState.tools
```

工具调用期间将状态映射为用户可读的提示。

- `web_search` 显示正在搜索网页
- 网页读取工具显示正在读取来源
- 工具错误显示提供商返回的简短原因

### 4.3 搜索结果

搜索结果归一化为来源记录。

```ts
type Source = {
  title: string;
  url: string;
  snippet?: string;
  publishedAt?: string;
};
```

回答消息保存来源记录，消息展示区提供来源标题和可点击链接。来源字段随本机会话持久化，后续打开历史对话时继续显示。

## 5. 平台传输

### 5.1 桌面端

优先使用 Tauri 启动本地 `pi-web-access` MCP 进程，前端通过受控桥接调用。进程生命周期绑定当前助手会话或应用实例，停止会话时取消未完成请求。

桌面端通过 Tauri 启动 `pi-web-access-mcp`，找不到本机命令时回退到 `npx -y pi-web-access@0.48.0`。当前版本没有把 Node runtime 或 npm 包打进桌面包，发布前需要随包提供运行时或改用固定 Gateway。

### 5.2 Web 和移动端

浏览器和移动端使用 MCP Streamable HTTP Gateway。前端配置 Gateway 地址，并将当前 API Key 作为可选 Bearer 凭据发送。Gateway 内部运行 `pi-web-access` 并连接 OpenAI Responses endpoint。本任务只接入客户端传输，不新增 Gateway 服务。

Gateway 不接收笔记库写入权限。它只处理网络搜索工具请求。

## 6. 数据和权限

- 联网搜索关闭时，不向 Agent 暴露网络工具
- 只有模型通过工具调用发出的搜索词会发往 Gateway 或搜索服务
- 宿主不自动把未引用笔记正文放入搜索词
- 搜索结果进入当前模型上下文和当前会话历史
- API Key 只进入本地 MCP 子进程环境变量或 Gateway 请求头，不进入 Agent prompt、工具结果、普通日志或 IndexedDB 会话消息
- 用户撤销联网授权后，立即关闭 MCP 连接并使待处理调用失效

## 7. 错误处理

需要覆盖以下情况。

- MCP 初始化失败
- `tools/list` 失败或工具缺失
- OpenAI Key 无效
- 模型无权限
- Responses endpoint 不支持 `web_search`
- 搜索超时
- Gateway 返回非 MCP 响应
- 用户停止对话
- 网络搜索成功但最终模型回复失败

搜索调用失败时保留用户输入和已产生的普通笔记工具结果，允许用户重试。

## 8. 测试和验收

### 自动化测试

- MCP 初始化和工具发现
- MCP 工具参数转发
- 工具取消和超时
- 搜索结果来源归一化
- 搜索关闭时不注册网络工具
- API Key 不出现在日志和历史记录
- OpenAI Responses Gateway 的受控成功和失败响应

### 人工验收

1. 填写 Responses Base URL、模型 ID 和临时 Key。
2. 测试连接，确认模型和 `web_search` 工具均可用。
3. 输入“搜索最新的 OpenAI Web Search 文档”。
4. 观察搜索状态、最终回答和来源链接。
5. 关闭联网搜索，再发送同样问题，确认不会发起网络工具调用。
6. 搜索过程中点击停止，确认 MCP 调用和模型请求均停止。
7. 打开历史对话，确认来源仍然可见。
8. 使用笔记写入请求，确认搜索结果不会跳过原有写入预览。

3. 将网络工具接入 `runTurn`，完成状态和取消处理。
4. 增加来源模型、历史持久化和消息展示。
5. 增加设置项和权限开关。
6. 增加 HTTPS Gateway 传输配置。
7. 执行 Web 构建、桌面构建和受控端到端验收。
8. 完成差异自审、回归测试和任务交付记录。
