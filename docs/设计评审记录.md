# WeNote 设计评审记录

> 评审时间：2026-11-20
> 对象：[产品与技术设计.md](./产品与技术设计.md)
> 评审目标：找出会影响数据一致性、跨端实现和后续扩展的设计问题，并在进入编码前完成修订。

## 1. 评审结论

当前设计可以作为 Phase 0 的基础，但需要先冻结同步协议、Asset 生命周期、分享快照和产品阶段边界。已修复的问题已经回写到主设计文档。

核心产品边界已经明确。

- 一个服务端支持多个独立账户。
- 每个账户可以拥有多个 Vault。
- 账户之间可以分享笔记、目录、图片和附件。
- 接收分享后复制到接收者自己的 Vault。
- 第一版使用文件级同步，不实现多人实时协作。
- Markdown 中的内部图片和附件使用稳定的 HTTPS Asset URL。

## 2. 本次修复的问题

### P0 级别

#### 文件并发判断使用了错误的粒度

原设计容易把 Vault 级别的 `base_revision` 当作文件冲突依据。现在改为使用 `base_version_id` 或 `base_content_hash` 判断单个文件是否被修改，`vault_revision` 只用于增量拉取。

#### Asset 没有进入完整数据模型

原设计描述了 Asset URL，但数据库表和本地文件映射不完整。现在增加了 `assets`、`file_asset_refs`、`upload_sessions`，并让 Asset 关联 Vault 中的附件 File 和当前版本。

#### S3 说明和 HTTPS URL 要求存在冲突

原设计的一处文字仍然提到 Markdown 使用相对路径。现在统一为 Markdown 保存 WeNote 稳定 HTTPS URL，S3、MinIO 和本地文件系统只作为后端存储。Asset URL 只使用 `asset_id`，文件名通过响应头提供，避免附件重命名改变正文中的 URL。

#### 分享链接缺少附件授权路径

分享笔记时，正文中的私有 Asset 不能直接使用发送者的普通资源权限。现在增加分享会话访问 Asset 的接口，并规定分享快照需要记录引用依赖，避免把长期分享令牌重复放进图片 URL。

#### 事务提交后的通知可能丢失

原设计在数据库提交后直接发送 WebSocket 通知。现在增加 `outbox_events`，由 Worker 重试通知、索引和预览任务。客户端仍然通过 revision 增量拉取恢复状态。

### P1 级别

#### 产品范围和研发阶段不一致

Android、JSON、XMind、实时预览和思维导图曾经同时出现在第一阶段范围中，但研发计划放在后续 Phase。现在核心版本聚焦桌面端和网页端同步，Android、JSON、XMind 和增强编辑体验进入后续阶段。

#### 离线粘贴图片没有明确处理方式

现在由客户端生成稳定 `asset_id`，根据 Vault 的 `public_base_url` 生成 HTTPS URL。图片可以先进入本地队列，Asset 上传完成后再提交服务端正文版本。

#### 分享接受操作缺少幂等和大目录处理

现在要求所有状态变更支持 `Idempotency-Key`。目录分享接受返回异步导入任务，避免重复复制文件和附件。

#### 文件版本与 Blob 的关系不够清晰

现在 File 只保存当前版本引用，历史内容由 FileVersion 通过 `blob_id` 引用 Blob。文件重命名和存储后端迁移不会改变历史版本含义。

## 3. 仍需在编码前确定的事项

### 3.1 Markdown URL 的部署策略

主设计已经按服务器实例配置 `public_base_url`。需要在部署配置中要求该地址使用稳定的 HTTPS 域名，所有 Vault 共用同一个资源域名，避免同一个服务端产生多套不可迁移的资源地址。

### 3.2 分享权限

建议首版只提供 `view`、`download` 和 `import`。分享者可以撤销分享，分享链接可以设置过期时间和密码。细粒度的评论、编辑来源和转发限制可以后置。

### 3.3 历史版本保留策略

需要确定默认保留时间、单个 Vault 配额和 Change Log 压缩策略。服务端需要维护 `min_available_revision`，旧客户端通过 manifest 快照恢复。

### 3.4 外部文件变更

需要确定客户端发现用户手动写入相对图片链接时的行为。建议提供“导入为 Asset 并改写为 HTTPS URL”的命令，同时保留普通外部 HTTPS 图片链接。

### 3.5 插件执行边界

建议第一版只允许内置插件参与服务端索引和渲染。第三方插件先运行在客户端和网页沙箱中，待权限模型、签名和资源限制稳定后再允许服务端执行。

### 3.6 SQLite 与 PostgreSQL 的边界

建议 SQLite 只支持单实例服务端。多实例、多人高并发和后台任务分离使用 PostgreSQL。两种数据库需要共用迁移测试和同步协议测试。

## 4. 推荐的下一步

先实现以下最小闭环。

```text
多账户登录
  -> 创建 Vault
  -> Mac 或 Windows 绑定本地目录
  -> Markdown 和 Asset 上传
  -> 网页编辑
  -> 文件版本和冲突处理
  -> 账户间分享快照
  -> 接收者导入自己的 Vault
  -> 笔记和附件分开导出
```

完成这个闭环后，再接入 Android、插件市场、XMind 和大文件增强。这样可以先验证最重要的数据模型和同步协议。
