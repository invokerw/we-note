# 笔记库 UI 风格规范与修复方法

用户在列表里学会重命名一篇笔记后，从正文或手机菜单进入同一操作，应当直接认出目标、输入框、确认和取消。此规范适用于 Web、桌面、Android，以及打开和保存笔记所经过的登录、分享、同步入口。三栏尺寸和手机逐屏导航沿用[笔记工作区设计](笔记工作区设计.md)，主题遵循用户在[个人外观设置](tasks/FEAT-20261125-appearance-schedule.md)中的选择。当前迁移范围见[修复清单](笔记库UI修复清单.md)。

## 主题与布局

- Web 与本地 React 入口共用笔记库的 Ant Design `ConfigProvider` 配置，使用中文文案、统一字体、主色、圆角、控件尺寸和浅深色算法。笔记库沿用蓝色强调色，管理后台的紫色属于后台主题。[现有 Provider 示例](../apps/web/src/AdminUI.tsx)
- Mantine `AppShell` 继续负责目录、笔记列表和正文的布局。控件由 Ant Design 提供，现有树、编辑器画布和触屏专用容器可保留自身交互，并消费同源主题变量。桌面同步首页使用静态 HTML 时也应引用这组变量。
- 为纸面、侧栏、浮层、正文、辅助文字、分隔、悬停、选中、焦点和危险状态分别配置语义颜色。使用当前设备外观生成它们；菜单、弹窗、消息即使挂载到 `body` 也必须拿到同一主题。收窄 `.layout button` 等全局选择器，逐处删除已由组件提供的覆盖。
- 常规表单使用统一的默认高度、字号和圆角，紧凑尺寸用于连续工具栏。图标居中于固定点击区，树节点预留相同图标宽度。手机返回、更多、完成和底栏按钮沿用 48 × 48 CSS 像素的触控目标。长文件名截断时保留可读的完整路径。

## 控件与交互

| 场景 | 规则 | 迁移举例 |
| --- | --- | --- |
| 执行动作 | 使用 `Button` 区分主、次、文本和危险操作。同一个表单有明确的提交动作。执行期间提供加载状态并防止重复提交。图标按钮提供可读名称，禁用态和键盘焦点清晰可见。 | 创建笔记使用主按钮，取消使用次按钮，永久删除的最终确认使用危险按钮。已保存与保存中分别显示状态。 |
| 输入与选择 | 使用 `Form` 组织标签、说明和字段错误。`Input`、密码框、`Select`、单选组、复选框、时间选择按数据类型使用。即时生效的二态设置可使用开关。 | 重命名显示原路径、名称及重名提示。校验失败保留输入并聚焦出错字段。外观定时错误显示在对应时间字段旁。 |
| 弹窗与确认 | 普通表单使用统一 `Modal` 标题、关闭入口和操作区；桌面表单底部按取消、提交排列。确认文案写明动作和对象，永久删除还要说明后果。手机的短操作列表可使用底部面板。 | 创建库、上传保存路径和文件改名使用应用内表单。将 `prompt`、`confirm` 的同步分支改成等待结果后执行，同一动作只提交一次。取消或关闭应保留原草稿和选中项。 |
| 菜单与选择 | 桌面右键、行尾更多、工具栏更多共用菜单项定义和图标。手机复用动作顺序、禁用原因和危险色。当前项有可见选中标记，以及可供辅助技术读取的状态。 | 选择编辑模式后回显当前模式；列表和正文菜单均能到达相同的重命名表单。键盘支持方向键、确认和 Escape，关闭后焦点回到合理位置。 |
| 多层界面 | 弹窗内的选择器、菜单和二次确认须正确叠放。Android 系统返回应先关闭最上层；关闭子菜单时停留在父界面。 | 迁移原生 `dialog` 时同步对接返回处理，并测试先关选择列表、再关设置弹窗、最后返回笔记列表。[现有返回处理](../apps/web/src/PhoneUI.tsx) |
| 结果与状态 | 字段错误显示在字段下方；区块加载和读取失败在区块内显示，适用时提供重试；完成复制、保存等短反馈使用统一消息。空列表解释当前范围并给出适用动作。 | “请查收验证邮件”使用成功或信息提示。搜索中、零结果、读取失败显示不同文案，避免失败信息被短时消息吞掉。 |
| 专用编辑面 | Markdown、脑图和白板保持各自的正文排版、命令及绘图手势。WeNote 提供的标题栏、工具按钮、设置表单和状态反馈遵循同一主题。 | 编辑器主题通过变量适配。编辑时切换外观，应保留选区、撤销记录和未保存内容。 |

## 修复一个入口的步骤

1. 从列表、正文、右键与手机更多找到对应调用方，记录现有名称、默认值、权限、草稿保护、提交方法和取消返回位置。优先复用已有的业务操作。
2. 从正常入口写失败测试。以重命名为例，分别从列表和正文进入，检查对话框名称、原路径、初值、冲突提示；模拟取消、重复提交和请求失败，验证文件和草稿的实际状态。
3. 在共享主题下替换控件或接入已有表单，分别传入 Web 和本地的读写回调。移除该入口遗留的原生提示框、局部按钮颜色和重复菜单定义。
4. 复核正常、悬停、焦点、选中、禁用、加载、错误状态，覆盖浅色、深色、宽屏与手机。核对实际计算样式和可读性；录入任务记录时分别注明浏览器、桌面应用和 Android 真机或模拟器的验证结果。
